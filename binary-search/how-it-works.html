How binary search works

A short guide to the guessing game: why guessing the middle is so powerful, how many guesses you can expect, and when the trick stops working.

Back to the game

The idea in one sentence

Binary search guesses the middle of the remaining range. The answer “higher” or “lower” tells you which half cannot contain the secret, so you throw that half away and repeat.

In the game you are the one making the guesses. The computer plays the part of a sorted list: it can only tell you which side the secret is on.

Worked example: find 100 in 1–100

Suppose the secret is 100. Each row guesses the midpoint of the range that is still possible, then keeps only the half that could contain the answer.

Why each guess halves the search space

A reply of “higher” rules out every number at or below your guess. “Lower” rules out every number at or above it. Because you guessed the middle, you discard about half of what was left, whichever answer you get.

After 7 halvings, at most one number can still be possible. Halving is what makes binary search fast: doubling the range only adds one extra guess.

The log2 formula

If there are n possibilities, then after k guesses about n / 2k possibilities remain. We need that to fall to 1, so k must be at least log2(n). Round up because you cannot make a fraction of a guess:

guesses ≤ ceil(log₂(n))

For 1–100 there are n = 100 possibilities. 26 = 64 is not enough, but 27 = 128 covers them all, so ceil(log₂(100)) = 7. That is why the game reports 7 as the optimal maximum for the default range.

Binary search vs linear search

Linear search checks numbers one at a time from the start. Binary search throws half away each time. For small ranges the difference is minor; for big ones it is enormous.

1–10,00010,000 guesses14 guesses

Linear search does have one advantage: it works on any list, sorted or not.

One catch: the data must be sorted

“Higher” and “lower” are only useful when the values are in order. In a sorted list, knowing that the secret is bigger than your guess means everything at or below that position can be safely skipped.

On an unsorted list, a bigger value might be hiding anywhere — even in the half you just discarded. So binary search needs sorted data (and sorting has its own cost). The guessing game works because the number line is naturally ordered.

Click a question to reveal its answer.

1. You guess 50 in a 1–100 game and hear “Lower — try a smaller number”. How many numbers are still possible?
49 numbers: 1 through 49. Your guess of 50 and everything above it has been ruled out.
2. Why can't binary search be used directly on an unsorted list?
Because “higher” or “lower” only tells you which half to keep if the values are ordered. Without order you cannot safely discard half the list, so you would have to check items one by one.
3. About how many guesses would binary search need for 1–1,000?
At most 10, because 29 = 512 is too small and 210 = 1,024 covers 1,000. That is ceil(log₂(1000)) = 10.
